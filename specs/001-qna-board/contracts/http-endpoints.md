# HTTP 엔드포인트 계약

서버 렌더링 HTML 서비스. 모든 문구는 한국어, 모든 시각은 `YYYY-MM-DD HH:mm`(KST). 계약 테스트(`tests/contract/`)는 이 문서를 그대로 검증한다.

공통:
- 세션 쿠키 `sid`(HttpOnly, SameSite=Lax).
- 모든 POST는 폼 필드 `csrf`가 세션 값과 같아야 하며 아니면 `403`.
- 응답 헤더: `Content-Security-Policy: default-src 'self'`, `X-Content-Type-Options: nosniff`.

## 공통 오류 응답

| 상황 | 응답 |
|------|------|
| 미로그인(GET 화면) | `401` + "로그인이 필요합니다." + 로그인 링크. 질문·답변 내용 비노출 |
| 미로그인(POST) | `401`, 저장 없음, "로그인이 필요합니다." |
| 답변 권한 없음 | `403`, 저장 없음, "답변 권한이 없습니다." |
| 존재하지 않는 질문 | `404` + "존재하지 않는 질문입니다." + 목록 링크 |
| 검증 실패 | `400`, 같은 폼을 다시 렌더링(입력한 제목·내용 유지), 입력란에 `aria-describedby`로 연결된 오류 문구 |

## 엔드포인트

| # | 메서드 경로 | 인증 | 설명 |
|---|-------------|------|------|
| 1 | `GET /login` | 불필요 | 로그인 폼 |
| 2 | `POST /login` (`emp_no`, `password`) | 불필요 | 성공 `303 → /` + 쿠키 발급. 실패 `401` "사번 또는 비밀번호가 올바르지 않습니다." |
| 3 | `POST /logout` | 필요 | 세션 폐기, `303 → /login` |
| 4 | `GET /` (`program_id?`, `page?`) | 필요 | 질문 목록 |
| 5 | `GET /questions/new` | 필요 | 질문 작성 폼 |
| 6 | `POST /questions` | 필요 | 질문 등록 |
| 7 | `GET /questions/:id` | 필요 | 질문 상세 + 답변 |
| 8 | `POST /questions/:id/answers` | 필요 + 답변 담당자 | 답변 등록 |

정적: `GET /static/style.css` (인증 불필요, 저장소 내 파일).

### 4. `GET /`
- `program_id`: 비어 있으면 전체. 값이 있으면 trim 후 그 ID의 질문만(정확 일치). 형식 오류·미등록 값은 오류 없이 빈 목록.
- `page`: 1부터, 기본 1, 한 페이지 20건, 최신 등록순(`id DESC`).
- 200 본문: 행마다 제목(상세 링크), 프로그램 ID, 작성일(KST), 답변 수. 필터 해제 링크.
- 빈 결과: 필터 없음 → "등록된 질문이 없습니다." / 필터 있음 → "해당 프로그램 ID의 질문이 없습니다."

### 6. `POST /questions`
- 폼: `csrf`, `form_token`, `program_id`, `title`, `body`.
- 성공: `303 → /questions/:id`.
- 실패 `400` 문구:
  - 프로그램 ID: 누락 "프로그램 ID를 입력해 주세요." / 형식 "프로그램 ID 형식이 올바르지 않습니다." / 미등록 "등록되지 않은 프로그램 ID입니다."
  - 제목: 누락 "제목을 입력해 주세요." / 100자 초과 "제목은 100자 이내로 입력해 주세요."
  - 내용: 누락 "내용을 입력해 주세요." / 4,000자 초과 "내용은 4,000자 이내로 입력해 주세요."
- `program_id` 필드가 둘 이상 오면 `400` "프로그램 ID 형식이 올바르지 않습니다."(질문 하나에 프로그램 ID는 정확히 하나, FR-002).
- `form_token`은 서버가 발급한 무작위 토큰이다. 검증 실패(400) 때는 같은 토큰을 폼에 다시 넣는다(저장 성공 시에만 소비). 이미 저장에 쓰인 토큰을 다시 보내면 새로 저장하지 않고 이미 등록된 질문 상세로 `303`.
- 로그: `question.create` (`result`, `ref_id`=질문 id, `user_id`).

### 7. `GET /questions/:id`
- 200: 프로그램 ID, 제목, 내용, 작성자 이름, 작성일시(KST), 답변 전체(등록순, 작성자 이름·일시). 답변 0건이면 "아직 답변이 없습니다."
- 현재 사용자가 답변 담당자일 때만 답변 폼 표시(부가 처리). 담당자 목록은 응답에 포함하지 않는다.
- `:id`가 숫자가 아니거나 없으면 `404`.

### 8. `POST /questions/:id/answers`
- 폼: `csrf`, `form_token`, `body`.
- 검사 순서: 로그인(401) → 답변 담당자 여부(403) → 질문 존재(404) → 내용 검증(400: "답변 내용을 입력해 주세요." / 4,000자 초과 "답변은 4,000자 이내로 입력해 주세요.") → 저장.
- 성공: `303 → /questions/:id`.
- 권한 없음이면 DB 쓰기 없음. 로그: 거부 시 `auth.denied`(`ref_id`=질문 id, `user_id`), 성공 시 `answer.create`.

## 로그 계약 (NFR-LOG)
JSON 한 줄. 허용 필드는 아래 표뿐이며, 그 밖의 필드는 로거가 버린다.

| 필드 | 필수 | 값 |
|------|------|----|
| event | O | 아래 이벤트 목록 중 하나 |
| at | O | ISO 8601 UTC (로거가 붙임) |
| result | O | `ok` / `denied` / `invalid` / `error`, 접근 로그는 상태코드 숫자 문자열 |
| ref_id | | 내부 식별자(질문 id 등) |
| user_id | | `users.id` (내부 식별자) |
| method | | 접근 로그 전용: `GET` / `POST` |
| route | | 접근 로그 전용: 경로 **템플릿**(`/questions/:id`). 실제 id·쿼리스트링 없음 |

이벤트: `login`, `auth.required`, `auth.denied`, `question.create`, `answer.create`, `http.access`, `programs.load_failed`.
이름·사번·제목·본문·쿼리스트링·비밀번호는 어떤 필드에도 들어가지 않는다.
