# Feature Specification: 사내 프로그램 문의 QnA 게시판

**Feature Branch**: `001-qna-board`

**Created**: 2026-11-12

**Status**: Draft

**Input**: User description: "사내 프로그램 문의 QnA 게시판. 프로그램 이용 직원이 사용법, 오류, 권한 관련 질문을 올리고 허가된 담당자가 답한다. 질문에는 프로그램 ID를 반드시 입력하고, 프로그램 ID로 질문을 거를 수 있다. 답변은 사전에 지정된 사용자(사번 목록)만 쓸 수 있다. 답변 채택, 사내 SSO 연동, 사내 프로그램 DB 실시간 연동은 이번 범위 밖이다."

## 배경과 목적

지금은 사내 프로그램에 대한 같은 문의가 메신저와 메일로 반복해서 들어온다. 질문과 답변이
한곳에 쌓이고, 프로그램 ID로 찾아볼 수 있으면 직원은 먼저 기존 답변을 확인할 수 있고
담당자는 같은 답을 되풀이하지 않아도 된다.

## 용어

- **프로그램 이용 직원**: 로그인한 일반 사용자. 질문을 올리고, 질문과 답변을 읽는다.
- **답변 담당자**: 사전에 지정된 사번 목록에 포함된 사용자. 일반 사용자 권한에 더해 답변을 쓴다.
- **프로그램 ID**: 문의 대상 사내 프로그램을 가리키는 식별자. 질문마다 정확히 하나를 입력한다.
- **허용 프로그램 ID 목록**: 질문에 사용할 수 있는 프로그램 ID의 집합.

## Clarifications

### Session 2026-11-13

- Q: 프로그램 ID는 어떤 형식을 올바른 것으로 봐야 하는가? → A: 영문 대문자 4자 + 숫자 4자, 또는 그 뒤에 영문 대문자 1자 추가 (`^[A-Z]{4}[0-9]{4}[A-Z]?$`)
- Q: 허용 프로그램 ID 목록은 누가 어떤 방법으로 등록·갱신하는가? → A: 시스템 관리자가 운영 절차로 관리한다(화면 기능 없음)
- Q: 질문·답변·작성자 정보의 보관 기간은? → A: 영구 보관(삭제 없음)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 프로그램 ID를 붙여 질문 올리기 (Priority: P1)

프로그램 이용 직원이 사용법, 오류, 권한에 관한 질문을 제목과 내용, 프로그램 ID와 함께 올린다.
올린 질문은 목록에 바로 나타난다.

**Why this priority**: 질문이 쌓이지 않으면 게시판 자체가 성립하지 않는다. 메신저·메일로
흩어지던 문의를 한곳으로 모으는 핵심 기능이다.

**Independent Test**: 로그인한 사용자가 올바른 프로그램 ID로 질문을 등록하고, 목록과 상세에서
같은 질문과 프로그램 ID가 보이면 통과한다. 이것만 구현해도 문의를 한곳에 모을 수 있다.

**Acceptance Scenarios**:

1. **Given** 로그인한 사용자가 질문 작성 화면에 있고 허용 프로그램 ID 목록에 `PRGM0001`이 있을 때,
   **When** 제목 "결재 화면이 열리지 않아요", 내용, 프로그램 ID `PRGM0001`을 입력하고 등록하면,
   **Then** 질문이 등록되어 상세 화면으로 이동하고, 상세 화면에 프로그램 ID `PRGM0001`과
   제목이 표시되며, 질문 목록 맨 위에 같은 질문이 1건 추가된다.
2. **Given** 질문이 등록된 상태에서, **When** 사용자가 질문 목록을 열면,
   **Then** 각 행에 제목, 프로그램 ID, 작성일(KST), 답변 수가 표시된다.
3. **Given** 프로그램 ID를 입력하지 않았을 때, **When** 등록을 누르면,
   **Then** 질문은 등록되지 않고 목록 건수는 그대로이며, 입력란 근처에
   "프로그램 ID를 입력해 주세요."가 표시되고 입력했던 제목과 내용은 유지된다.
4. **Given** 프로그램 ID에 형식이 틀린 값(예: `prg 1`)을 입력했을 때, **When** 등록을 누르면,
   **Then** 질문은 등록되지 않고 목록 건수는 그대로이며,
   "프로그램 ID 형식이 올바르지 않습니다."가 표시된다.
5. **Given** 형식은 맞지만 허용 프로그램 ID 목록에 없는 값(예: `PRGM9999`)을 입력했을 때,
   **When** 등록을 누르면, **Then** 질문은 등록되지 않고 목록 건수는 그대로이며,
   "등록되지 않은 프로그램 ID입니다."가 표시된다.
6. **Given** 로그인하지 않은 사용자가, **When** 질문 작성 화면 또는 질문 등록 요청에 접근하면,
   **Then** 질문은 등록되지 않고 로그인 안내("로그인이 필요합니다.")가 표시된다.

### User Story 2 - 질문 찾아 읽기와 프로그램 ID로 거르기 (Priority: P2)

로그인한 사용자가 질문 목록과 상세 화면을 읽고, 프로그램 ID로 질문을 거른다.
새로 질문하기 전에 같은 문의가 이미 있는지 확인할 수 있다.

**Why this priority**: 반복 문의를 줄이는 효과는 기존 질문과 답변을 찾아볼 수 있을 때 생긴다.

**Independent Test**: 서로 다른 프로그램 ID의 질문이 여러 건 있을 때 특정 프로그램 ID로 거르면
해당 질문만 남는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `PRGM0001` 질문 3건과 `PRGM0002` 질문 2건이 있을 때,
   **When** 프로그램 ID 필터에 `PRGM0001`을 선택하면,
   **Then** 목록에 3건만 표시되고 모든 행의 프로그램 ID가 `PRGM0001`이다.
2. **Given** 필터가 적용된 상태에서, **When** 필터를 해제하면, **Then** 전체 5건이 표시된다.
3. **Given** 질문이 없는 프로그램 ID로 거르면, **Then** 목록에
   "해당 프로그램 ID의 질문이 없습니다."가 표시된다.
4. **Given** 질문 목록에서, **When** 질문 하나를 선택하면,
   **Then** 상세 화면에 프로그램 ID, 제목, 내용, 작성일시(KST), 달린 답변 전체가 표시된다.
5. **Given** 존재하지 않는 질문 번호(예: 삭제되었거나 잘못된 주소)로 상세 화면을 열면,
   **Then** "존재하지 않는 질문입니다."가 표시되고 질문 목록으로 돌아가는 링크가 있다.
6. **Given** 허용 프로그램 ID 목록에 없는 값으로 거르려 하면,
   **Then** 목록은 비어 있고 "해당 프로그램 ID의 질문이 없습니다."가 표시된다.
7. **Given** 로그인하지 않은 사용자가 목록이나 상세 화면에 접근하면,
   **Then** 질문 내용은 노출되지 않고 "로그인이 필요합니다."가 표시된다.

### User Story 3 - 지정된 담당자가 답변하기 (Priority: P3)

답변 담당자가 질문에 답변을 쓴다. 담당자가 아닌 로그인 사용자는 읽기만 할 수 있다.

**Why this priority**: 질문에 답이 달려야 문의가 해결된다. 다만 질문 등록과 열람이 먼저 있어야
답변의 대상이 생긴다.

**Independent Test**: 지정된 사번 사용자는 답변이 등록되고, 지정되지 않은 사용자는 화면에서도
서버에서도 답변이 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 답변 담당자로 지정된 사용자가 질문 상세 화면에 있을 때,
   **When** 답변 내용을 입력하고 등록하면,
   **Then** 답변이 질문 아래에 추가되어 답변 수가 1 늘고, 답변 작성일시(KST)가 표시된다.
2. **Given** 답변 담당자가 아닌 로그인 사용자가 질문 상세 화면에 있을 때,
   **Then** 답변 입력란과 등록 버튼이 보이지 않고, 질문과 기존 답변은 읽을 수 있다.
3. **Given** 답변 담당자가 아닌 로그인 사용자가 화면을 거치지 않고 답변 등록을 직접 요청하면,
   **When** 서버가 요청을 받으면,
   **Then** 서버는 요청을 거부하고 답변은 저장되지 않으며 답변 수는 그대로이다.
   요청자에게는 "답변 권한이 없습니다."가 전달된다.
4. **Given** 로그인하지 않은 사용자가 답변 등록을 요청하면,
   **Then** 서버는 요청을 거부하고 답변은 저장되지 않는다. "로그인이 필요합니다."가 전달된다.
5. **Given** 답변 담당자가 존재하지 않는 질문에 답변을 등록하려 하면,
   **Then** 답변은 저장되지 않고 "존재하지 않는 질문입니다."가 표시된다.
6. **Given** 답변 담당자가 내용을 비워 둔 채 등록하면,
   **Then** 답변은 저장되지 않고 "답변 내용을 입력해 주세요."가 표시된다.

### Edge Cases

- 프로그램 ID 앞뒤에 공백이 있으면 어떻게 처리하는가? 앞뒤 공백은 제거한 뒤 검사한다. 공백만 입력하면 "누락"으로 본다.
- 제목이나 내용이 비어 있거나 공백뿐이면? 등록되지 않고 "제목을 입력해 주세요.", "내용을 입력해 주세요."가 표시된다.
- 제목이 100자를 넘거나 내용이 4,000자를 넘으면? 등록되지 않고 글자 수 초과 문구가 표시된다.
- 등록 버튼을 연속으로 두 번 누르면? 질문은 1건만 등록된다.
- 질문에 답변이 한 건도 없으면? 상세 화면에 "아직 답변이 없습니다."가 표시된다.
- 질문이 한 건도 없으면? 목록에 "등록된 질문이 없습니다."가 표시된다.
- 답변 담당자 목록에서 제외된 사용자의 이전 답변은? 이미 쓴 답변은 그대로 유지되고, 새 답변만 거부된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 로그인한 사용자는 누구나 질문을 작성할 수 있어야 한다. 질문은 제목, 내용, 프로그램 ID를 가진다.
- **FR-002**: 질문 등록 시 프로그램 ID는 필수이며, 질문 하나에 프로그램 ID는 정확히 하나여야 한다.
- **FR-003**: 프로그램 ID가 비어 있으면 질문을 등록하지 않고 "프로그램 ID를 입력해 주세요."를 표시해야 한다.
- **FR-004**: 프로그램 ID 형식이 올바르지 않으면 질문을 등록하지 않고 "프로그램 ID 형식이 올바르지 않습니다."를 표시해야 한다. 형식 규칙: 영문 대문자 4자 + 숫자 4자(예: `PRGM0001`), 또는 여기에 영문 대문자 1자를 더한 9자(예: `PRGM0001A`). 정규식으로는 `^[A-Z]{4}[0-9]{4}[A-Z]?$`이며, 대소문자를 구분한다(소문자는 형식 오류).
- **FR-005**: 형식은 맞지만 허용 프로그램 ID 목록에 없는 값이면 질문을 등록하지 않고 "등록되지 않은 프로그램 ID입니다."를 표시해야 한다. 허용 목록의 관리 방법: 시스템 관리자가 운영 절차(설정 파일 또는 DB 직접 반영)로 등록·갱신한다. 화면에서 목록을 추가·수정하는 기능은 없으며, 사내 프로그램 DB와의 실시간 연동은 범위 밖이다.
- **FR-006**: 질문에 태그 기능을 두지 않는다. 분류는 프로그램 ID로만 한다.
- **FR-007**: 질문 목록의 각 행과 질문 상세 화면에 프로그램 ID가 표시되어야 한다.
- **FR-008**: 질문 목록은 프로그램 ID로 거를 수 있어야 하며, 필터를 해제하면 전체 목록으로 돌아가야 한다.
- **FR-009**: 질문 목록은 최신 등록순으로 보여 주며, 한 화면에 20건씩 표시한다.
- **FR-010**: 답변은 사전에 지정된 사번 목록의 사용자만 등록할 수 있어야 한다.
- **FR-011**: 서버는 모든 답변 등록 요청에서 요청자가 답변 담당자인지 검사하고, 아니면 거부해야 한다. 화면에서 입력란을 숨기는 것만으로 대신할 수 없다.
- **FR-012**: 답변 담당자가 아닌 로그인 사용자는 질문과 답변을 읽을 수만 있어야 한다.
- **FR-013**: 질문 하나에는 여러 개의 답변이 달릴 수 있어야 하며, 답변은 등록 순서대로 표시한다.
- **FR-014**: 로그인하지 않은 사용자는 질문 작성, 열람, 답변을 할 수 없어야 하며 "로그인이 필요합니다."를 보게 된다.
- **FR-015**: 존재하지 않는 질문(상세 조회, 답변 등록 대상)에 접근하면 "존재하지 않는 질문입니다."를 표시해야 한다.
- **FR-016**: 답변 채택 기능은 제공하지 않는다.
- **FR-017**: 질문과 답변에는 작성자와 작성일시가 기록되어야 한다.
- **FR-018**: 오류로 등록이 거부되어도 사용자가 입력한 제목과 내용은 화면에 유지되어야 한다.

### 비기능 요구사항

**보안**

- **NFR-SEC-001**: 모든 화면과 데이터 요청은 로그인한 사용자만 접근할 수 있어야 한다.
- **NFR-SEC-002**: 답변 권한은 서버에서 검사한다(FR-011). 권한 없는 요청이 거부된 사례는 테스트로 증명되어야 한다.
- **NFR-SEC-003**: 사용자가 입력한 문자열은 다른 사용자의 화면에서 스크립트나 마크업으로 실행되지 않아야 한다(입력값은 글자 그대로 표시).
- **NFR-SEC-004**: 서비스는 사내망에서만 접근할 수 있고, 외부 CDN이나 외부 호스트에 의존하지 않는다(헌법 V).
- **NFR-SEC-005**: 답변 담당자 사번 목록은 일반 사용자에게 화면이나 응답으로 노출되지 않아야 한다.

**응답 시간** (정상 부하, 동시 사용자 100명 이하 기준)

- **NFR-PERF-001**: 질문 목록(필터 적용 포함)과 상세 화면은 요청 후 2초 이내에 표시된다(95백분위수).
- **NFR-PERF-002**: 질문 등록과 답변 등록은 완료 후 3초 이내에 결과 화면이나 오류 문구가 표시된다(95백분위수).
- **NFR-PERF-003**: 질문이 10,000건 쌓인 상태에서도 NFR-PERF-001을 만족한다.

**접근성**

- **NFR-A11Y-001**: 질문 작성, 목록 필터, 답변 작성 등 모든 기능을 마우스 없이 키보드만으로 수행할 수 있다.
- **NFR-A11Y-002**: 모든 입력란에 보이는 레이블이 있고, 오류 문구는 해당 입력란과 연결되어 보조 기술에 전달된다.
- **NFR-A11Y-003**: 오류와 상태는 색깔만으로 구분하지 않고 문구로도 표시하며, 본문 글자와 배경의 명도 대비는 4.5:1 이상이다.

**로그**

- **NFR-LOG-001**: 질문 등록, 답변 등록, 권한 거부, 로그인 필요 거부는 사건 종류, 시각, 결과, 내부 식별자로 기록한다.
- **NFR-LOG-002**: 이름과 사번 등 개인정보는 어떤 로그에도 남기지 않는다(헌법 III). 질문·답변 본문도 로그에 남기지 않는다.

**개인정보 보관 기간**

- **NFR-PRIV-001**: 질문·답변·작성자 정보는 영구 보관한다. 보관 기간 만료에 따른 자동 삭제나 비식별 처리는 하지 않는다.
- **NFR-PRIV-002**: 개인정보는 로그인한 사용자에게 화면에서 보이는 범위(작성자 표시) 외에는 내보내거나 외부로 전송하지 않는다.

**한국어와 KST 표시**

- **NFR-L10N-001**: 버튼, 안내, 오류 문구를 포함한 모든 화면 문구는 한국어로 표시한다(헌법 IV).
- **NFR-L10N-002**: 화면에 표시하는 모든 날짜와 시각은 KST(UTC+9)이며 `YYYY-MM-DD HH:mm` 형식이다. UTC 2026-11-12 15:30에 등록된 질문은 "2026-11-13 00:30"으로 표시된다.

### Key Entities *(include if feature involves data)*

- **질문**: 프로그램 이용 직원이 올린 문의. 제목, 내용, 프로그램 ID, 작성자, 작성일시를 가진다. 답변을 여러 개 가질 수 있다.
- **답변**: 답변 담당자가 질문에 쓴 글. 내용, 작성자, 작성일시를 가지며 질문 하나에 속한다.
- **프로그램 ID**: 문의 대상 프로그램의 식별자. 허용 프로그램 ID 목록의 항목이어야 한다.
- **답변 담당자**: 답변을 쓸 수 있도록 사전에 지정된 사용자의 사번 목록.
- **사용자**: 로그인한 직원. 일반 사용자 또는 답변 담당자 중 하나의 권한을 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 로그인한 사용자가 올바른 프로그램 ID로 질문을 올리는 데 걸리는 시간이 입력 시작부터 등록 완료까지 2분 이내이다.
- **SC-002**: 질문 등록을 처음 시도한 사용자의 90%가 도움말 없이 등록에 성공한다.
- **SC-003**: 프로그램 ID로 거르면 결과 목록의 100%가 선택한 프로그램 ID와 일치한다.
- **SC-004**: 답변 담당자가 아닌 사용자의 답변 등록 시도가 100% 거부되고 저장된 답변은 0건이다.
- **SC-005**: 프로그램 ID 누락, 형식 오류, 허용 목록에 없는 값으로 등록을 시도한 경우 100% 등록되지 않고 각각 정해진 한국어 오류 문구가 표시된다.
- **SC-006**: 게시판 운영 3개월 후, 메신저와 메일로 들어오는 프로그램 문의 건수가 도입 전 같은 기간 대비 50% 줄어든다.
- **SC-007**: 질문 등록 후 7일 안에 답변이 달린 질문의 비율이 80% 이상이다.

## Assumptions

- 대상 사용자는 사내망에 접속한 직원이며, 로그인 수단은 계획 단계에서 정한다. 사내 SSO 연동은 이번 범위 밖이다.
- 질문과 답변 작성자의 이름은 로그인한 사용자 사이에서 화면에 표시된다. 로그에는 남기지 않는다.
- 이번 범위에는 질문·답변의 수정과 삭제, 첨부파일, 알림(메일·메신저), 검색(키워드)이 없다. 필요하면 후속 기능으로 다룬다.
- 질문 제목은 100자, 내용은 4,000자, 답변 내용은 4,000자 이내로 제한한다.
- 허용 프로그램 ID 목록도 시스템 관리자가 같은 방식으로 관리한다(화면 기능 없음).
- 답변 담당자 사번 목록은 시스템 관리자가 별도로 관리하며, 목록 변경은 화면 기능이 아니라 운영 절차로 처리한다.
- 응답 시간 목표(NFR-PERF)는 동시 사용자 100명 이하, 질문 10,000건 이하 규모를 기준으로 한다.
- SC-006의 기준선은 도입 직전 3개월의 메신저·메일 문의 건수를 별도로 집계해 정한다.
- 헌법(`.specify/memory/constitution.md`) v1.0.0의 다섯 개 원칙을 모두 따른다.
