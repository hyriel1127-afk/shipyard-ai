# Feature Specification: QnA 게시판 읽기 전용 스냅샷 내보내기

**Feature Branch**: `003-qna-snapshot`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "사내 QnA 게시판의 읽기 전용 스냅샷 내보내기. 목적: 답변 검색 에이전트가 게시판 DB를 직접 읽지 않고 파일로만 질문과 답변을 찾게 한다."

## Clarifications

### Session 2026-11-13

- Q: 질문이 하나도 없을 때 만드는 파일에도 맨 위 생성 시각(KST) 줄을 넣을까요? → A: 넣는다. 생성 시각 줄과 "내보낼 질문이 없습니다" 문구만 쓴다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 질문과 답변을 한 파일로 내보내기 (Priority: P1)

운영 담당자가 내보내기를 실행하면 게시판의 모든 질문과 그 답변이 `data/snapshot/qna.md` 한 파일에 담긴다. 답변 검색 에이전트는 게시판 DB에 접근하지 않고 이 파일만 읽어 질문과 답변을 찾는다.

**Why this priority**: 이 기능의 존재 이유다. 파일이 만들어지지 않으면 에이전트가 읽을 자료가 없다.

**Independent Test**: 질문과 답변이 있는 상태에서 내보내기를 실행하고, 생성된 파일에 모든 질문과 답변이 정해진 항목대로 들어 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 질문이 1건 이상 등록되어 있고, **When** 내보내기를 실행하면, **Then** `data/snapshot/qna.md`가 생성되고 모든 질문이 각각 질문 번호, 프로그램 ID, 제목, 본문, 질문 등록일을 가진 항목으로 들어간다.
2. **Given** 답변이 달린 질문이 있고, **When** 내보내기를 실행하면, **Then** 해당 질문 항목 아래에 각 답변의 본문과 답변 등록일이 함께 들어간다.
3. **Given** 답변이 아직 없는 질문이 있고, **When** 내보내기를 실행하면, **Then** 그 질문은 파일에 포함되며 답변이 없음이 표시된다.
4. **Given** 한 질문에 답변이 여러 개 있고, **When** 내보내기를 실행하면, **Then** 답변이 모두 등록 순으로 들어간다.
5. **Given** 이미 `data/snapshot/qna.md`가 있고, **When** 내보내기를 다시 실행하면, **Then** 파일이 현재 게시판 내용으로 완전히 대체되고 이전 내용이 섞여 남지 않는다.

---

### User Story 2 - 개인정보 제외와 생성 시각 표시 (Priority: P1)

스냅샷에는 작성자의 사번과 이름이 어떤 형태로도 들어가지 않는다. 파일 첫 줄에는 생성 시각이 KST로 적혀, 에이전트와 사람이 자료가 얼마나 최신인지 알 수 있다.

**Why this priority**: 개인정보 유출은 되돌릴 수 없고, 생성 시각이 없으면 오래된 자료를 최신으로 오해한다.

**Independent Test**: 작성자 이름과 사번이 알려진 데이터로 내보낸 뒤, 파일 전체에서 그 값이 검색되지 않고 첫 줄에 KST 시각이 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 작성자 이름·사번이 있는 질문과 답변이 있고, **When** 내보내기를 실행하면, **Then** 파일 어디에도 질문 작성자와 답변 작성자의 이름·사번이 없다.
2. **Given** 질문 제목이나 본문에 우연히 작성자 이름이 문장으로 쓰여 있어도, **When** 내보내기를 실행하면, **Then** 본문은 있는 그대로 내보낸다(작성자 필드만 제외하며 본문 내용은 가공하지 않는다).
3. **Given** 내보내기를 실행하고, **When** 파일을 열면, **Then** 파일의 첫 줄에 생성 시각이 KST(UTC+9)로 표시되어 있다.
4. **Given** UTC 기준 자정 직전·직후에 내보냈고, **When** 생성 시각을 보면, **Then** 날짜가 KST 기준으로 올바르게 표시된다.
5. **Given** 질문·답변 등록일이 있고, **When** 파일을 보면, **Then** 모든 등록일도 KST로 표시된다.

---

### User Story 3 - 데이터를 바꾸지 않는 안전한 내보내기 (Priority: P1)

내보내기는 읽기 전용이다. 실행 전후로 게시판의 질문, 답변, 계정 등 어떤 데이터도 달라지지 않는다.

**Why this priority**: 에이전트용 자료를 만들다가 운영 데이터를 훼손하면 안 된다.

**Independent Test**: 실행 전후의 게시판 데이터를 비교해 동일함을 확인한다.

**Acceptance Scenarios**:

1. **Given** 게시판에 질문과 답변이 있고, **When** 내보내기를 실행하면, **Then** 실행 전후 질문·답변·계정 데이터가 완전히 같다.
2. **Given** 내보내기가 중간에 실패했고, **When** 게시판을 확인하면, **Then** 게시판 데이터에는 아무 변화가 없다.

---

### User Story 4 - 질문이 없거나 저장 폴더가 없는 경우 (Priority: P2)

질문이 하나도 없어도 내보내기는 성공하며, 폴더가 없으면 스스로 만든다. 에이전트가 항상 읽을 파일이 존재하고 그 의미가 분명해야 한다.

**Why this priority**: 초기 운영이나 새 환경에서 흔한 상황이며, 빈 상태에서도 파일 규약이 깨지지 않아야 한다.

**Independent Test**: 질문이 0건인 상태, `data/snapshot` 폴더가 없는 상태 각각에서 내보내기를 실행해 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** 질문이 하나도 없고, **When** 내보내기를 실행하면, **Then** 파일이 생성되고, 첫 줄 생성 시각(KST) 다음에 "내보낼 질문이 없습니다" 한 줄만 있다(다른 내용 없음).
2. **Given** 질문이 하나도 없고 이전 스냅샷에 질문이 들어 있었고, **When** 내보내기를 실행하면, **Then** 이전 질문 내용은 남지 않고 "내보낼 질문이 없습니다" 파일로 대체된다.
3. **Given** `data/snapshot` 폴더가 없고, **When** 내보내기를 실행하면, **Then** 폴더가 만들어지고 파일이 정상 생성된다.
4. **Given** 폴더를 만들 수 없거나 파일을 쓸 수 없고, **When** 내보내기를 실행하면, **Then** 실패 원인을 한국어로 알리고 실패로 종료하며, 게시판 데이터는 바뀌지 않는다.
5. **Given** 기존 `qna.md`가 있고 쓰기 도중 실패했고, **When** 파일을 확인하면, **Then** 기존 파일이 그대로 남아 있고 불완전한 파일이나 임시 파일은 남지 않는다.

---

### Edge Cases

- 본문에 마크다운 기호, 줄바꿈, 코드 블록, 구분선과 같은 문자열이 있을 때: 질문 항목 경계가 깨져 다른 질문과 섞여 읽히지 않아야 한다.
- 제목·본문이 매우 긴 경우: 잘라내지 않고 전체를 내보낸다.
- 질문이 매우 많은 경우: 한 파일로 모두 내보낸다(분할하지 않는다).
- 한글, 이모지 등 다국어 문자: 깨지지 않고 보존된다.
- 내보내기 도중 새 질문이 등록되는 경우: 한 시점의 일관된 내용만 담긴다(질문과 그 답변이 어긋나지 않는다).
- 다른 프로그램(예: 에이전트)이 `qna.md`를 열고 있어 교체할 수 없는 경우: 쓰기 실패로 처리해 한국어 오류 안내와 실패 종료를 하고, 기존 파일은 그대로 둔다.
- 내보내기를 연속으로 두 번 실행: 생성 시각을 제외하면 같은 내용이다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 게시판의 모든 질문과 답변을 `data/snapshot/qna.md` 단일 파일로 내보내야 한다.
- **FR-002**: 각 질문 항목은 질문 번호, 프로그램 ID, 제목, 본문, 질문 등록일을 포함해야 한다.
- **FR-003**: 각 질문 항목은 그 질문에 달린 모든 답변의 본문과 답변 등록일을 포함해야 하며, 답변은 등록 순(등록일이 같거나 시계가 어긋나도 등록된 순서)으로 나열한다.
- **FR-004**: 답변이 없는 질문도 파일에 포함하고, 답변이 없음을 표시해야 한다.
- **FR-005**: 시스템은 질문 작성자와 답변 작성자의 사번과 이름을 파일에 내보내서는 안 된다.
- **FR-006**: 파일의 첫 줄에 생성 시각을 KST(UTC+9)로 적어야 한다(질문이 없는 경우에도 같다).
- **FR-007**: 파일에 표시되는 모든 날짜·시각(질문 등록일, 답변 등록일 포함)은 KST여야 한다.
- **FR-008**: 내보내기는 게시판의 어떤 데이터도 생성·수정·삭제해서는 안 된다.
- **FR-009**: 질문이 하나도 없으면 첫 줄 생성 시각(KST)과 "내보낼 질문이 없습니다" 문구만 쓴 파일을 만들어야 한다(질문 항목, 그 밖의 안내 문구는 쓰지 않는다).
- **FR-010**: `data/snapshot` 폴더가 없으면 시스템이 만들어야 한다.
- **FR-011**: 이미 파일이 있으면 새 내용으로 완전히 대체해야 한다.
- **FR-012**: 폴더 생성이나 파일 쓰기에 실패하면 한국어 오류 안내와 함께 실패로 종료해야 하며, 기존 스냅샷 파일은 그대로 유지하고 불완전한 파일이나 임시 파일을 남겨서는 안 된다.
- **FR-013**: 각 질문 항목은 본문 내용과 관계없이 항목 경계를 구분할 수 있어야 하고, 질문 번호로 질문을 특정할 수 있어야 한다.
- **FR-014**: 작성자 사번·이름을 오류 메시지나 로그에 남겨서는 안 된다(헌법 III).
- **FR-015**: 파일 안내 문구와 오류 메시지는 한국어여야 한다(헌법 IV).
- **FR-016**: 내보내기는 외부 네트워크로 어떤 것도 전송하지 않아야 한다(헌법 V).

### Key Entities *(include if feature involves data)*

- **스냅샷 파일**: 특정 시점의 질문과 답변을 담은 읽기용 문서. 생성 시각(KST)과 질문 항목 목록으로 이루어진다. 매 실행마다 전체가 새로 만들어진다.
- **질문 항목**: 질문 번호, 프로그램 ID, 제목, 본문, 질문 등록일, 답변 목록을 가진다. 작성자 정보는 갖지 않는다.
- **답변 항목**: 답변 본문과 답변 등록일을 가지며 질문 하나에 속한다. 작성자 정보는 갖지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 내보내기 후 `qna.md`에 담긴 질문 수가 게시판의 질문 수와 100% 일치하고, 답변 수도 100% 일치한다.
- **SC-002**: 작성자 필드에서 가져온 이름·사번 값을 파일 전체에서 검색했을 때 일치 0건이다(본문에 사용자가 직접 쓴 문자열은 원문 그대로이므로 대상이 아니다).
- **SC-003**: 내보내기 전후 게시판 데이터 비교에서 차이가 0건이다.
- **SC-004**: 질문 1,000건과 답변 3,000건이 있을 때 내보내기가 1분 안에 끝난다.
- **SC-005**: 질문 0건일 때 파일 내용이 생성 시각 줄과 "내보낼 질문이 없습니다" 한 줄, 이 둘뿐이다.
- **SC-006**: 폴더가 없는 상태에서 내보내기 성공률이 100%이다.
- **SC-007**: 답변 검색 에이전트가 게시판 DB에 접근하지 않고 이 파일만으로 임의의 질문과 그 답변을 번호나 프로그램 ID로 찾을 수 있다.
- **SC-008**: 같은 데이터로 두 번 내보냈을 때 생성 시각 줄을 제외한 내용이 100% 동일하다.

## Assumptions

- 한 질문에 답변이 여러 개일 수 있다(기존 게시판 명세 기준). 모두 내보낸다.
- 내보내기는 운영 담당자가 필요할 때 직접 실행한다. 자동 주기 실행은 이번 범위에 포함하지 않는다.
- 질문 순서는 질문 번호 오름차순이다.
- 파일은 사내 저장소 안에서만 사용하며 접근 통제는 기존 환경을 따른다.
- 본문은 가공(마스킹, 요약)하지 않고 원문 그대로 내보낸다. 본문 속 개인정보 제거는 범위 밖이다.
- 날짜 표시 형식은 기존 게시판 화면의 KST 표기와 같은 형식을 따른다.

## 범위 밖 (이번에 하지 않을 것)

- 실시간 동기화(게시판 변경을 즉시 파일에 반영)
- 외부 전송(파일을 외부 시스템·서비스로 보내기)
