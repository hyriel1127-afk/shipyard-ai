요청: $ARGUMENTS

0. 요청이 비었거나, 추적 중인 파일에 커밋하지 않은
   변경이 있으면 시작하지 않고 사람에게 묻는다.
   추적하지 않는 새 파일은 상관하지 않는다.
1. planner 서브에이전트에게 요청을 넘겨
   docs/plan.md를 만들게 한다.
2. plan.md에서 의존성이 없는 작업끼리 묶어
   coder 서브에이전트를 묶음마다 하나씩 동시에 띄운다.
   같은 파일을 고치는 묶음은 동시에 띄우지 않는다.
3. 모든 coder가 끝나면 reviewer에게 git diff를 넘기고,
   판정을 docs/review.md에 저장한다.
   reviewer의 반려 기준을 바꾸거나 빼라고 지시하지 않는다.
4. review.md가 반려면 지적 사항만 coder에게
   다시 넘긴다. 이 과정은 최대 2번까지만 한다.
   반려 사유가 테스트의 기대값 때문이면 스스로
   고치지 않고 사람에게 묻고 멈춘다. 그 전에는
   계획과 구현을 멈추지 않고 끝까지 진행한다.
   2번 뒤에도 반려면 남은 지적을 보여 주고 멈춘다.
5. 통과하면 변경 요약을 보여 주고 멈춘다.
   push는 하지 않는다.

review.md에는 회차마다 판정, 대상(git diff 범위),
npm test 통과 수를 남긴다. 덮어쓰지 않고 아래에 더한다.
